System Architecture Reference

Factory Inventory Management

A Vue 3 single-page app talking to a FastAPI backend over plain HTTP. There is no database — the backend reads seven JSON files into memory once at startup and filters them on every request.

Vue 3.4 + Vite FastAPI + Pydantic Python ≥3.11 no database :3000 → :8001

Data Flow, Step by Step

  1. 01
    User adjusts a filter.

    Time Period, Warehouse, Category, or Order Status, set in FilterBar.vue.

  2. 02
    Shared state updates.

    The useFilters() composable holds the selection in refs so every view reads the same filter state.

  3. 03
    The view calls api.js.

    It builds a URLSearchParams query, skipping any filter left at 'all'.

  4. 04
    Axios sends the request.

    A GET to http://localhost:8001/api/… — e.g. /api/orders?warehouse=West&month=Q3-2025.

  5. 05
    FastAPI filters in memory.

    apply_filters() and filter_by_month() run against the module-level lists — no query language, just list comprehensions.

  6. 06
    Pydantic validates the shape.

    Each route's response_model checks and serializes the result before it leaves the server.

  7. 07
    The view re-renders.

    JSON lands in a ref (allOrders, inventoryItems); a computed property derives the displayed shape.

Constraints Worth Knowing

No persistence

Everything lives in Python lists for the life of the process. Restarting main.py resets all state back to the JSON fixtures.

No auth, open CORS

allow_origins=["*"] and no login check — intentional for a local demo, not safe to deploy as-is.

One filter system, four axes

Time Period, Warehouse, Category, and Order Status pass through as query params to nearly every endpoint; inventory has no time axis.

Public repo hygiene

client/.npmrc pins the public npm registry and the client lockfile is gitignored, so a private registry never leaks into a commit.
